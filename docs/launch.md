## 掘金

### 标题

换个新对话就得重讲项目？我开源了 handoff

### 正文

用 Agent 做长任务，代码和材料明明还在，但换个新对话，还是要把项目背景重新讲一遍。

更麻烦的是，交接文档不一定跟得上项目：旧版本、过期待办和已经完成的工作混在一起，接手时还得重新确认。

我把这个问题整理成了一个小 skill，叫 **handoff（项目交接）**。

它的核心思路很简单：**先核实，再交接。** 从工作区的真实状态出发，把接手需要的四件事整理清楚：

- **当前状态**：哪个版本有效，哪些结果已经验证。
- **下一步**：什么还没完成，接下来应该做什么。
- **关键约束**：哪些数据、已有修改和重要决策需要保留。
- **证据入口**：去哪里找对应的文件和记录。

例如，旧交接还写着“生成演示并发布”，当前版本却已经有了新的候选，正在等待审阅。此时下一步应该更新为审阅候选，旧记录作为历史保留。

交接正文只保留当前接手需要的信息，详细材料通过文件索引按任务读取，避免把整段历史反复复制进新对话。

它是一个纯指令的 `SKILL.md` 文件包，MIT 开源，不需要额外部署服务。

安装到当前项目的 Codex：

```bash
npx skills add jidekaixin2dian/handoff --skill handoff --agent codex
```

然后在对话里发送：

```text
$handoff 我要换个新对话继续这个项目。
请核实当前状态，更新交接入口，保留关键证据和下一步。
```

仓库里有使用说明和交接前后的例子：

https://github.com/jidekaixin2dian/handoff

如果你也经常用 Agent 做长任务，欢迎试试。换对话时最容易丢的是项目背景、关键决策，还是当前进度？也欢迎分享你的交接方式。
