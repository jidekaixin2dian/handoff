## 短版：开发者群 / 动态

做长任务时，换个新对话，最麻烦的往往是重新解释项目：哪个版本有效？哪些结果已经验证？下一步是什么？

我做了一个小 skill：**handoff · 项目交接**。

它从工作区的真实状态整理一个当前入口，把状态、下一步、约束和证据分开；旧交接保留为历史，细节按任务再展开。

纯指令，MIT 开源。没有清理请求，不顺手删文件；不把离线检查通过写成人工验收完成。

## 长版：技术社区 / 项目分享

### 标题

开源一个小 skill：让新对话接得上旧项目

### 正文

用 Agent 做长任务，容易遇到一种情况：代码和材料已经更新，交接文档还停在上个版本；几份交接复制同一段历史，旧待办和当前任务混在一起。

我把这件事整理成了一个小 skill，叫 **handoff（项目交接）**。

它做的是：先从工作区核实当前状态，然后把四件事说清楚——现在在哪、下一步做什么、哪些约束必须保留、按任务去哪里找证据。

一个典型例子是：旧交接写着“生成演示并发布”，当前版本清单却已经是新的候选。核对之后，下一步应该是请负责人审阅，而不是重做演示或沿用旧发布指令。旧记录仍保留，但标为历史。

这份 skill 也明确保留原始数据、冻结评估、人工评分、哈希和已有修改。精简交接文档不等于授权清理项目文件；“还能下载”也不自动意味着可以删。

它是一个纯指令的 `SKILL.md` 文件包，不需要配套服务。当前在 Codex 的项目安装路径做了下载检查，也完成了格式检查、12 类场景静态审查和一次隔离文件演练。尚未进行跨模型评测或 token 节省测量。

安装：

```bash
npx skills add jidekaixin2dian/handoff --skill handoff --agent codex
```

使用：

```text
$handoff 我要换个新对话继续这个项目。
请核实当前状态，更新交接入口，保留关键证据和下一步。
```

仓库：https://github.com/jidekaixin2dian/handoff

欢迎反馈具体的交接场景和实际不合适的行为。分享例子前，请移除凭据和私有资料。
