# 交接前后：一个虚构项目

以下使用虚构项目展示交接文档的结构。

旧交接写着 v1.1，并让下一位 Agent“生成演示并发布”。但当前版本清单已到 v2.4 候选，演示文件存在，人工验收尚未完成。直接沿用旧任务，会从错误状态开工。

## 交接前

```text
当前版本：v1.1
下一步：生成演示，然后发布。
其后粘贴数页历史实施记录与运行日志……
```

## 核对之后

```text
最后核对：2026-10-05

当前状态
  v2.4 候选文件已存在，哈希与版本清单一致。
  冻结记录报告离线协议通过；本次没有重跑该协议。
  人工验收待完成；正式质量评估未运行；尚未发布。

下一步
  请负责人审阅候选。保留文件，等待反馈。

关键约束
  原始数据、冻结结果、人工评分与已有修改原样保留。
  如果之后要求新评估，使用新轮次，保留旧轮。

按任务找证据
  审阅候选 → 当前版本清单、候选文件
  了解评估边界 → 冻结协议记录、人工评分
  理解历史决策 → 原始决策记录

历史
  2026-09-15 的 v1.1 交接保留为历史概要。
  它的旧发布计划不是当前任务，也不产生新授权。
```

信息没有凭空减少：当前入口变短，详细材料留在原处，按任务链接。下一位接手时先读当前状态，再按实际工作展开证据。

## 交接过长时怎么拆

同一个项目又过了三个月：正文涨到 300 多行，`下一步` 攒了 11 条，实施记录、评估协议、发布脚本各有一份自己的说明。这时不该继续往 `handoff.md` 里追加。

```text
handoff.md（≈60 行）
  最后核对：2027-01-08
  当前状态      有效版本 v3.1；v2.4 已归档；人工验收通过（负责人 2026-11-02）。
  下一步        1. 补齐灰度回滚脚本  2. 定发布窗口
  关键约束      冻结评估勿改；原始日志只读
  按任务找证据
    想继续写脚本      → docs/plan-rollback.md
    想复现构建        → docs/build.md
    想核对评估边界    → eval/frozen/（只读）
    想了解为什么改版  → history/2026-10-release-postmortem.md
  历史          2026-10-05 v2.4 交接：候选待审 → 原文件归档于 history/
```

拆分规则：

- 一行一个任务，任务是动词短语（“复现构建”而不是“构建相关”）。
- 链接只指向权威文件，不指向二手复述；同一个可变事实只留一处。
- 被挪走的旧正文进 `history/`，文件名带日期；`handoff.md` 里只留一行结论和链接。
- 删除前搜一遍引用：如果别的文档链接到被删章节，先改链接再删。
