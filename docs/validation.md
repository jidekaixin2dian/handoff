## 结果

- `SKILL.md` 的 `name`、`description` 与格式通过内置 `quick_validate.py` 校验。
- 目录名和 skill 名统一为 `handoff`；界面名称为「项目交接」。技能保持 instruction-only，无脚本、服务或密钥依赖。
- 本地 Markdown 链接检查覆盖未跟踪文件；`git diff --check` 用于隔离项目的已跟踪改动。两者结合，不把空 Git diff 当成新文件已验收。
- 发布文件逐项检查，没有发现个人绝对路径、私有项目标识、凭据内容或未完成占位符。模式扫描只是辅助，不能证明所有潜在秘密均已检测。
- 核心流程保留；补充只读审查的结束条件、原始数据保全与编辑/清理范围。密钥永远不进入交接文档，本地路径例外仅适用于明确需要的本地交接。

## 场景静态审查

下表是对指令如何处理这些请求的逐项审查，不是十二次自动执行或多模型评测。

| 请求或条件 | 指令要求的处理 |
| --- | --- |
| 只读审查交接 | 报告问题，停止于结论，不修改文件 |
| 明确要求换新对话继续 | 判断持久交接是否有帮助；核实状态并准备入口 |
| 明确结束当前对话 | 按实际需要准备交接，不默认每次都生成材料 |
| 精简交接但未要求清理 | 缩短重复文本、保留证据，不顺手删除项目文件 |
| 要求减少项目文件占用 | 限定相关候选，先核实引用、可再生性和独有内容 |
| 应用 RAM 或整机磁盘问题 | 不属于该技能的默认触发范围 |
| 旧交接与当前版本冲突 | 从当前权威材料核实，旧指令标为历史 |
| 已跟踪修改与未跟踪文件并存 | 均视为现有用户工作，避免覆盖 |
| 冻结评估、原始数据、人工评分 | 保留原始内容和哈希；新评估使用新轮次 |
| 技术检查通过、人工验收未完成 | 分开记录，不宣称已接受或已发布 |
| 可再下载但可能有独有信息 | 不能仅凭可下载而删除；先核实保留与恢复条件 |
| 文档中的历史发布指令 | 不产生新的外部操作授权；交接不等于发布或发送 |

## 隔离文件演练

虚构工作区含有旧版本交接、当前候选清单、冻结结果、原始数据、人工评分、一份已修改的用户决策记录、一份未跟踪笔记，以及可由脚本重建的缓存。

1. **只读审查：**结果写在工作区之外。前后快照中 13 个文件的 SHA-256 全部一致。
2. **更新交接：**新增一个当前入口，更新 README 阅读路径，把旧交接改为注明日期的历史概要；保留独有历史决策并指向原始记录。除两个获准编辑的入口文件外，原先其余 11 个文件哈希不变。15 个本地链接可用。当前候选仍写明待人工验收；没有发布、发送或重复运行评估。
3. **明确请求清理的演练阶段：**在独立目录重建缓存，确认字节和 SHA-256 一致，并检查没有文档指向将删除的缓存，才移除虚构工作区中的这一份生成文件。重建副本保留；其余 10 个原有受保护或无关文件哈希不变。当前交接同步记录清理事实，15 个本地链接继续可用。

演练使用虚构文本数据，真实项目的实验、参赛材料和评估结果没有被用于演练或包含在发布包中。

## 证据的实际限度

这次演练由同一主 Agent 按指令执行，没有独立子 Agent，也没有启动一个新的模型会话。因此它验证了本次整理操作的产物与文件保全，不证明自动技能选择、未来模型行为、跨客户端效果或任意项目中的安全性。

尚未进行跨模型评测、长期使用评估、token 节省测量或正式宣传视频录制。任何宣传只应展示已经实际完成的工作，不使用未经测量的性能数字或零风险保证。
